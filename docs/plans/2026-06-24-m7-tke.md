### The prognostic column solver `integrate_tke` (`cvmix_tke.F90:415-987`) — the math to transcribe

Per column, `k=1..nlev+1` (`nlev=nln-nun+1`). Inputs `dzw(nlev)` (=`hnode(nun:nln)`),
`dzt(nlev+1)` (=`dz_trr`), `tke_old`, `Ssqr` (=`vshear2`), `Nsqr` (=`bvfreq2`), `forc_tke_surf`,
`dtime`, `rho_ref`, `grav`. Outputs `tke_new`, `KappaM_out`, `KappaH_out`.

```
P1 mixing length (:665-698):
   sqrttke = sqrt(max(0d0, tke_old))
   mxl     = sqrt(2D0)*sqrttke / sqrt(max(1d-12, Nsqr))
   ! Blanke-Delecluse limiter (tke_mxl_choice==2, the only ported branch):
   mxl(1)=0d0; mxl(nlev+1)=0d0
   do k=2,nlev:        mxl(k)=min(mxl(k), mxl(k-1)+dzw(k-1))
   mxl(nlev)=min(mxl(nlev), mxl_min+dzw(nlev))
   do k=nlev-1,2,-1:   mxl(k)=min(mxl(k), mxl(k+1)+dzw(k))
   mxl = max(mxl, mxl_min)
P2 diffusivities (:700-720):
   KappaM_out = min(kappaM_max, c_k*mxl*sqrttke)
   Rinum      = Nsqr / max(Ssqr, 1d-12)
   prandtl    = max(1d0, min(10d0, 6.6*Rinum))
   KappaH_out = KappaM_out / prandtl
P3 forcing (:723-734):
   K_diss_v   = Ssqr*KappaM_out                  ! shear production
   P_diss_v   = Nsqr*KappaH_out                  ! buoyancy (damping when N²>0)
   P_diss_v(1)= -forc_rho_surf*grav/rho_ref      ! forc_rho_surf=0 here ⇒ P_diss_v(1)=0
   forc       = K_diss_v - P_diss_v
   ! (l_lc Langmuir + .not.only_tke iw_diss terms are DEAD: l_lc=F, only_tke=T)
P4 implicit tridiag diffusion+dissipation (:747-827):
   ke(k) = alpha_tke*0.5*( KappaM_out(min(k+1,nlev)) + KappaM_out(max(k,2)) )   ! k=1..nlev
   c_dif(k)=ke(k)/(dzt(k)*dzw(k));  c_dif(nlev+1)=0
   b_dif(k)=ke(k-1)/(dzt(k)*dzw(k-1)) + ke(k)/(dzt(k)*dzw(k))                    ! k=2..nlev
   a_dif(k)=ke(k-1)/(dzt(k)*dzw(k-1));  a_dif(1)=0                              ! k=2..nlev+1
   ! surface Neumann BC (use_ubound_dirichlet=F):
   forc(1)  = forc(1) + (cd*forc_tke_surf**(3./2.))/dzt(1)
   b_dif(1) = ke(1)/(dzt(1)*dzw(1))
   ! bottom Neumann BC (use_lbound_dirichlet=F):
   b_dif(nlev+1) = ke(nlev)/(dzt(nlev+1)*dzw(nlev))
   a_tri = -dtime*a_dif
   b_tri = 1 + dtime*b_dif
   b_tri(2:nlev) = b_tri(2:nlev) + dtime*c_eps*sqrttke(2:nlev)/mxl(2:nlev)      ! DISSIPATION
   c_tri = -dtime*c_dif
   d_tri = tke_old + dtime*forc
   call solve_tridiag(a_tri,b_tri,c_tri,d_tri, tke_new, nlev+1)   ! reciprocal-multiply Thomas
P5 floor (:867-869, only_tke=T):  tke_new = max(tke_new, tke_min)
P6 diagnostics (Tbpr/Tspr/Tdif/Tdis/Twin/Tiwf/Tbck/Ttot/Lmix/Pr) — computed in Fortran order in
   local scratch, copied out at end. NOT load-bearing for tke/Av/Kv, but the tke_dump gate (M7a)
   checks them, so port them (cheap; read-after-write: P_diss_v/K_diss_v seed Tbpr/Tspr).
```

`solve_tridiag` (`cvmix_utils_addon.F90:116-149`): transcribe VERBATIM — row 1 is a DIRECT divide
(`m=b(1); x(1)=d(1)/m` at `:134-135`), but the elimination rows use the **reciprocal-multiply** form
(`fxa=1D0/m; cp(i)=c(i-1)*fxa; x(i)=(d(i)-cp(i-1)*…)*fxa`), NOT `c/m` — last-bit difference (C-port
lesson). Match the routine's exact operand/operation order line-for-line.

### The driver `calc_cvmix_tke` (`gen_modules_cvmix_tke.F90:378-660`)

   nln = nlevels_nod2D(node)-1;  nun = ulevels_nod2D(node)
   vshear2 = 0
   do nz = nun+1, nln:

### M7a — isolated TKE column, byte-exact `max|Δ|=0` gate (CONTROLLED REPLAY, 3 steps)

The make-or-break gate: lock the column algebra in isolation the way the C port's controlled replay
did (it caught the only real port bug, the `6.6` literal, then hit `1.1e-16`). ⚠️ **Step 1 is
DEGENERATE and must NOT be the only gate**: `tke=0` at init ⇒ at step 1 `tke_old=0` ⇒ `sqrttke=0` ⇒
`mxl→mxl_min`, `KappaM=KappaH=0`, `K_diss_v=P_diss_v=ke=0`, the tridiag collapses to `b_tri=1,d=0` ⇒
`tke_new=0`→floored to `tke_min`. So step 1 exercises ONLY input-assembly + `prandtl`; P3 (forcing),
P4 (tridiag with non-zero `ke` + the `c_eps·sqrttke/mxl` dissipation), P5 are first exercised at
**steps 2–3 where `tke_old≠0`** — which is exactly why the oracle `work_tke_dump` runs `run_length=3`.

**Harness = controlled replay of the EXISTING oracle `tke_dump`** (no rebuild). The dump emits, per
step + per gid, both the column INPUTS (`vshear2/bvfreq2/dztrr/tkeold` + scalar `normstress`) AND the
OUTPUTS (`tke/tkeav/tkekv` + intermediates `lmix/pr/tbpr/tspr/tdif/tdis`). FESOM3 INGESTS the
oracle's per-step input dumps straight into `integrate_tke` (reconstructing `dzw=hnode(nun:nln)` from
its own identical linfs mesh — `dzt`=`dztrr` is dumped) and emits the outputs → pure column algebra on
bit-identical inputs, all 3 steps. The intermediate tags (`lmix`=mxl, `pr`=prandtl, `tbpr/tspr`,
`tdif/tdis`) localize any drift to a single Part.
