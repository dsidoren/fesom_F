## Reframing (the "read the actual namelist" lesson, again)

The HANDOFF lumped "zstar/zlevel ALE" into M6 "beyond-paper". **The actual production `work_core`
namelist uses `which_ALE = 'zlevel'`** (`work_core/namelist.config:71`), NOT zstar. So:

- **M6a = zlevel** is NOT beyond-paper — it is the LAST reduced-gate downgrade between the current
  byte-exact state (linfs) and the TRUE paper-parity production config. M5 closed KPP+GM+Redi+sw_pene
  **on the reduced `linfs` free surface**; M6a swaps `linfs → zlevel` to finish paper parity.
- **M6b = zstar**, **M6c = TKE**, **M6d = aEVP** (`whichEVP=2`) are the genuine beyond-paper targets
  (staged oracle work-dirs `work_zstar_*`, `work_tke_dump`, `work_mevp_dump`).

Production `work_core` ALE config (verified from the namelists, not summaries):
`which_ALE='zlevel'`, `which_pgf='shchepetkin'` (DEFAULT — `oce_modules.F90:190`; not in any work_core
namelist), `min_hnode=0.5`, `lzstar_lev=4` (defaults), `use_partial_cell=.false.`, `use_cavity=.false.`,
`use_floatice=.false.`, `use_sw_pene=.true.` (done in M5c), `mix_scheme='KPP'`, `Fer_GM/Redi=.true.`.
⇒ all cavity / floatice / partial-cell branches are **DEAD** in the production path.

## The zlevel delta vs the proven linfs path (oracle map, verified)

The whole linfs dynamical core + column physics is byte-exact (M2–M5). zlevel changes these and ONLY
these (everything else — advection, EVP, KPP, GM, Redi, forcing — is unchanged):

1. **PGF**: linfs calls `pressure_force_4_linfs` (consumes `hpressure`); zlevel calls
   `pressure_force_4_zxxxx` → (which_pgf=shchepetkin) → `pressure_force_4_zxxxx_shchepetkin`
   (`oce_ale_pressure_bv.F90:2104-2339`). **Self-contained** (no `hpressure`): integrates
   `density_m_rho0` gradients over the evolving `Z_3d_n`/`helem` directly. Dispatch:
   `oce_ale.F90:3656-3661`.
2. **Per-step stiffness rebuild**: `update_stiff_mat_ale` (`oce_ale.F90:1892-2001`, ~110 lines, NEW)
   is called EVERY step for non-linfs (`oce_ale.F90:3921`, `if(.not. which_ale=='linfs')`) — it
   updates the SSH-stiffness 2nd term by `dhe=hbar(n+1/2)-hbar(n-1/2)` on elements. linfs builds the
   stiffness ONCE (`init_stiff_mat_ale` in setup) and never updates it.
3. **Thickness evolves**: `init_thickness_ale` zlevel branch (`oce_ale.F90:~1056-1128`, SSH into the
   surface layer at init); `vert_vel_ale` zlevel branch (hnode_new from `dhbar_total=hbar-hbar_old`,
   `Wvel(nzmin) -= dhbar_total/dt`, + local-zstar fallback when a layer would drop below
   `min_hnode·h`); `update_thickness_ale` LIVE (commit hnode + recompute `zbar_3d_n`/`Z_3d_n`,
   `exchange_elem(helem)`). The current port stubs `update_thickness_ale` as a linfs no-op
   (`oce_ale.F90:462-480`) and `vert_vel_ale` has no zlevel correction.
4. **Real freshwater flux replaces virtual salt**: `which_ALE/='linfs' ⇒ use_virt_salt=.false.`
   (`oce_setup_step.F90:120`). Then the `water_flux` terms become live in `compute_ssh_rhs_ale` /
   `compute_hbar_ale` / `vert_vel_ale` (`Wvel(nzmin) -= water_flux`), and in `oce_fluxes`
   (`ice_oce_coupling.F90`) the `virtual_salt` term is OFF and the ice-thermo freshwater split
   (thdgr/thdgrsn into `water_flux`) is ON. Forced/native only (unforced ⇒ water_flux=0 ⇒ all these
   terms vanish, so the unforced gate isolates the thickness machinery).

DEAD under production flags (do NOT port for M6a): cavity (`nzmin>1` branches, `use_cavity=F`),
floatice/use_pice (`oce_ale_vel_rhs.F90:94`, `ice_EVP.F90:580`, `use_floatice=F`), partial-cell PGF
methods (`use_partial_cell=F`), PP-mixing-zlevel (`oce_ale_mixing_pp.F90:46`, production is KPP),
the `oce_ale_pressure_bv.F90:369` linfs/cavity branch (zlevel-no-cavity skips it), split-explicit
subcycling (`use_ssh_se_subcycl=F`). Faithful-but-gated-off can come later (the M5c ghats precedent).

## Decomposition (mirror M4/M5: producer → unforced → forced/native → multi-rank)

- **M6a-1 — Shchepetkin PGF isolated byte-gate.** Port `pressure_force_4_zxxxx_shchepetkin` into a new
  `oce_pgf` routine (explicit-dataflow args, optional-`partit`, owned-element loop). Add a zlevel/
  shchepetkin variant to the CORE2 pressure gate (`fesom_pressuredump.F90` + the oracle
  `fesom_pressure_dump.F90`): configure `which_ALE=zlevel`, `which_pgf=shchepetkin`, call the new PGF
  on the prescribed state (rest η=0, so `Z_3d_n`=initial — non-vacuous for the ALGORITHM regardless of
  η), dump `pgf_x`/`pgf_y`, byte-gate `max|Δ|=0`. ⚠️ **L29 watch**: the subsurface bulk loop
  (`:2248-2280`) does length-3 array divides (`drho_dz = df10/dx10 + (...)/(dx20*dx21*dx10)*...`); both
  sides are local arrays (same aliasing → same codegen) but GATE it and keep `!DIR$ NOVECTOR` ready.
  Feed-forward producer, safest first gate.
- **M6a-2 — zlevel thickness machinery, UNFORCED lifecycle.** Byte-gate the UNFORCED zlevel CORE2
  lifecycle `max|Δ|=0` (SSH evolves from dynamics divergence ⇒ hnode evolves; water_flux=0 ⇒ the
  freshwater terms are dormant ⇒ this isolates the thickness/PGF/stiffness machinery from the M6a-3
  freshwater path). New gate `tools/run_lifecycle_zlevel_gate_core2.sh`. **DETAILED IMPLEMENTATION MAP
  (oracle code read 2026-06-24; FESOM3 inputs `dhe`/`hbar`/`hbar_old` [mesh], `CFL_z`=`dynamics%cfl_z`
  all already exist):**
  - **COLD-START SIMPLIFICATION:** the lifecycle cold-starts with hbar=0 ⇒ `init_thickness_ale`(zlevel)
    == (linfs) for the surface layer ⇒ FESOM3's existing rest-state init is correct at t=0. **Do NOT
    need to port init_thickness_ale(zlevel) for the cold-start gate** (port it later only for restart).
  - **`update_stiff_mat_ale` (NEW routine, oracle `oce_ale.F90:1892-2001`)** — add to `oce_ssh_rhs.F90`
    alongside `init_stiff_mat_ale`. `factor=g*dt*alpha*theta`; loop OWNED edges `ed`, both edge-nodes
    `row` (owned: `row≤nNodO`), both triangles `el(i)`: `fy(1:3) = -dhe(elem)*(gradient_sca(1:3)*
    edge_cross_dxdy(2i,ed) - gradient_sca(4:6)*edge_cross_dxdy(2i-1,ed))`; `if(i==2)fy=-fy; if(j==2)
    fy=-fy`; `SSH_stiff%values(npos)=SSH_stiff%values(npos)+fy*factor` (npos = the sparse positions of
    `elnodes(k)` in row's row, via `nn_pos`). BYTE-EXACT: the sparse structure (rowptr/nn_pos/values) is
    M2.6-proven; same edge order (1-rank = global) + same `dhe`/`gradient_sca`/`edge_cross_dxdy` ⇒
    identical accumulation. `dhe` is from the PREVIOUS step's `compute_hbar_ale` (lagged; step-1 dhe=0 ⇒
    stiffness unchanged step 1, matches oracle). Optional-`partit`, owned-edge loop (M6a-4-ready).
  - **`vert_vel_ale` zlevel branch (oracle `oce_ale.F90:2552-2753)`** — insert between the Wvel
    cumsum/divide and the `exchange_nod(Wvel/hnode_new)` (FESOM3 `oce_ale.F90:~367`). `if(which_ale==
    'zlevel')`: loop OWNED nodes; nzmin=ulevels_nod2D(n) (=1 no cavity), `dhbar_total=hbar(n)-hbar_old(n)`.
    THREE cases: (A, local-zstar shrink) `dhbar_total<0 .and. hnode(nzmin,n)+dhbar_total<=(zbar(nzmin)-
    zbar(nzmin+1))*min_hnode` → distribute over ≤`lzstar_lev` layers (max_dhbar2distr/CFL_z≥0.95 cap/
    cumsum/pack/the down-up `distrib_dhbar_int` loop); (B, return-to-zlevel) `dhbar_total>0 .and. any

    hnode_new(nzmin,n)=hnode(nzmin,n)+dhbar_total`. Then `Wvel(nzmin,n)-=water_flux(n)` (M6a-3; =0 here).
    Needs `lzstar_lev`/`min_hnode` (`mod_config`), `mesh%zbar`, `CFL_z`. **For the short cold-start gate

## Beyond-paper (after M6a closes paper parity)

- **M6b — zstar.** `which_ALE='zstar'` (`work_zstar_dump`/`work_zstar_kpp`/`work_zstar_tke`): the
  SSH change is distributed across ALL layers (`hnode*(1+η/H)`) instead of just the surface. Small delta
  on M6a (the `zstar` branches sit right next to the zlevel ones in init/update_thickness/vert_vel).
- **M6c — TKE.** CVMix classical TKE (`namelist.cvmix`, `mix_scheme='TKE'`, `work_tke_dump`/
  `work_linfs_tke`): the ONE stateful (prognostic `tke`) mixing scheme. Fresh validation, not a proven
  port. `tke_cd` from namelist; halo-exchange internal `tke_Av` before node→elem mean; Prandtl `6.6` double.
- **M6d — aEVP.** `whichEVP=2` (Bouillon 2013; `c_aevp=0.15`; `work_mevp_dump`). mEVP (whichEVP=1) was
  delivered in M3; aEVP is the deferred adaptive variant.
